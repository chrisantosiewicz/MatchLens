# MatchLens project rules

- Compute statistics deterministically; use AI for relevant interpretation and presentation.
- Ground factual claims in structured facts and supporting event IDs.
- Respect the viewer's selected clock in statistics, answers, recaps and alerts.
- Clearly label synthetic data and keep generation football-realistic. Validate multiple seeds; do not claim empirical calibration.
- Distinguish temporal association from causation. Never infer tracking or off-ball behavior from events.
- Distinguish template, live-model and fallback outputs. Configuration is not verified connectivity.
- Preserve a useful local demo when cloud services fail.
- Keep secrets out of source control, logs and browser code.
- Document reproducible setup, verification commands and known limitations.
- Add regression coverage for confirmed consequential bugs; avoid tests that merely repeat implementation logic.
- Defer video recognition, tracking, extra agents and major infrastructure unless essential to the demonstrated use case.
- Keep project facts and verification evidence in repository documentation. Do not claim live integration or reliability without recorded verification.
